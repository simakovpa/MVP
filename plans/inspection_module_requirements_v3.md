# Требования к разработке прототипа модуля для ведения испытаний и измерений (v.3)

## Общие сведения

Разработать прототип модуля для управления процессом испытаний и измерений в электроснабжающей организации. Центральным документом модуля должен быть **Протокол испытаний**.

## Основные функции

1. **Управление протоколами испытаний**: Создание, редактирование, просмотр и удаление протоколов
2. **Управление данными для протоколов**:
   - Измерительные приборы (замоканный список для селектов)
   - Подразделения-заказчики (иерархическая структура)
3. **Настройка работ**: Создание, редактирование и удаление видов работ с определением характеристик и условий измерений
4. **Внесение результатов измерений**: Предзаполненные таблицы с характеристиками, пустые поля для ввода значений

## Структура данных

### Подразделения-заказчики

Иерархическая структура из файла `Подразделения.txt` (9 филиалов, каждый с дочерними РЭС и участками)

### Виды испытаний

- Приёмо-сдаточные
- Периодические
- Профилактические
- Контрольные

### Настройка работ

Каждая работа имеет:

- Наименование
- Описание (необязательное)
- Перечень условий окружающей среды (зависит от работы и выводится над таблицей с перечнем измеряемых характеристик)
- Перечень измеряемых характеристик (группировка в блоки выводится в виде таблицы)

#### Примеры условий окружающей среды

- Температура воздуха
- Влажность воздуха
- Атмосферное давление
- Уровень шума
- Освещенность

#### Примеры блоков измеряемых характеристик

1. **Для нескольких единиц оборудования**:
   - Опорный блок:
     - Уровень загнивания
     - Диаметр ствола
     - Высота опоры
2. **Для одного оборудования с несколькими наборами измерений**:
   - Измерения заземления:
     - Сопротивление заземляющего контура
     - Площадь контактной поверхности
   - Измерения изоляции:
     - Сопротивление изоляции фазы А
     - Сопротивление изоляции фазы В
     - Сопротивление изоляции фазы С

### Метаданные протокола

- Номер протокола
- Дата проведения
- Вид испытаний
- Электролаборатория (выбор из замоканного списка)
- Подразделение-заказчик (иерархический выбор)
- Объект
- Вид работ (определяет набор характеристик и условий)
- Условия измерений (по работе)
- Результаты измерений (таблица с блоками характеристик, полями для ввода значений, статус соответствия НТД)
- Измерительные приборы (выбор из списка)
- Заключение (текстовое поле)
- Исполнители (список сотрудников из замоканного списка)
- Проверяющий (один сотрудник из замоканного списка)

## Технические требования

1. Использовать React + Ant Design
2. Для иерархических списков использовать TreeSelect
3. Все данные должны быть храняться локально (в состоянии приложения)
4. Формы должны быть адаптивными и поддерживать мобильные устройства
5. Валидация полей формы (обязательные поля, формат данных)
6. Поддержка русскоязычного интерфейса

## Файлы

- `description.md` - описание процесса ведения измерений
- `Подразделения.txt` - структура подразделений-заказчиков
- `rules.md` - правила для разработки
- `964 НМЭС-2023_КОС. 28-4-12.xlsx` - пример заполненного протокола
- `448 СМЭС-2023_ВЛ-0,4 кВ Ф-2 от КТП-95.xlsx` - дополнительный пример протокола

## Основные экраны

1. **Главный экран**: Карточки для доступа к:
   - Реестру протоколов
   - Настройке работ
2. **Реестр протоколов испытаний**: Таблица с протоколами, создание/редактирование/удаление
3. **Настройка работ**: Создание/редактирование/удаление видов работ с настройкой характеристик и условий
4. **План-график испытаний**: Placeholder для будущих версий

## Взаимодействие с работами

- Создание новой работы через форму с указанием:
  - Наименования и описания
  - Условий окружающей среды
  - Блоков измеряемых характеристик
- Редактирование существующей работы
- Удаление работы
- Просмотр списка всех работ

## Взаимодействие с протоколом

- Создание нового протокола через форму с предзаполненными характеристиками и условиями по выбранному виду работ
- Характеристики предзаполняются на основании выбранных в протоколе работ (множественный выбор из списка)
- Редактирование существующего протокола
- Просмотр деталей протокола
- Удаление протокола

## Дизайн требования

- Использовать компоненты Ant Design
- Цветовая схема: синий (#1890ff) как основной, зеленый для "соответствует", красный для "не соответствует"
- Легче читаемость таблиц
- Адаптивный макет для разных размеров экранов
- Для блоков характеристик используем Collapse для удобного просмотра

## Примеры данных

Для демонстрации прототипа должны быть подготовлены:

- 3 виды работ с разными наборами характеристик и условий
- 20 объектов
- 2 заполненных протокола
- 15 измеряемых характеристик (сгруппированных в 4 блока)

## Дополнительные требования

- Поддержка поиска по протоколам и работам
- Фильтрация протоколов по дате, виду испытаний, электролаборатории
- Экспорт протоколов в Excel (будущие версии)

## План разработки

1. Настройка проекта React + Ant Design
2. Создание главного экрана с карточками для доступа к модулям
3. Реализация экрана настройки работ с CRUD-операциями
4. Реализация экрана реестра протоколов с CRUD-операциями
5. Реализация модальной формы создания/редактирования протокола
6. Реализация таблицы с результатами измерений с блоками характеристик
7. Добавление возможности выбора вида работ и автоматического заполнения характеристик и условий
8. Реализация иерархического выбора подразделений
9. Наполнение прототипа тестовыми данными
10. Тестирование и оптимизация

## Ограничения прототипа

- Данные хранятся локально (не сохраняются при перезагрузке)
- Нет интеграции с внешними системами
- Функционал плана-графика не реализован
- Экспорт в Excel не реализован
- Реестры сотрудников и электролабораторий скрыты (замоканные значения)
