# Требования к разработке прототипа модуля для ведения испытаний и измерений (v.2)

## Общие сведения

Разработать прототип модуля для управления процессом испытаний и измерений в электроснабжающей организации. Центральным документом модуля должен быть **Протокол испытаний**.

## Основные функции

1. **Управление протоколами испытаний**: Создание, редактирование, просмотр и удаление протоколов
2. **Управление данными для протоколов**:
   - Измерительные приборы (замоканный список для селектов)
   - Подразделения-заказчики (иерархическая структура)
3. **Внесение результатов измерений**: Предзаполненные таблицы с характеристиками, пустые поля для ввода значений

## Структура данных

### Подразделения-заказчики

Иерархическая структура из файла `Подразделения.txt` (9 филиалов, каждый с дочерними РЭС и участками)

- Приёмо-сдаточные
- Периодические
- Профилактические
- Контрольные

### Виды работ и измеряемые характеристики

Вид работы определяет набор измеряемых характеристик. Примеры:

- "Измерение сопротивления заземляющего контура":
  - Сопротивление заземляющего контура
  - Сопротивление изоляции фазы А
  - Сопротивление изоляции фазы В
  - Сопротивление изоляции фазы С
- "Замеры загнивания деревянных опор":
  - Уровень загнивания опоры №1
  - Уровень загнивания опоры №2
  - Уровень загнивания опоры №3

### Метаданные протокола

- Номер протокола
- Дата проведения
- Вид испытаний
- Электролаборатория (выбор из замоканного списка)
- Подразделение-заказчик (иерархический выбор)
- Объект
- Вид работ (определяет набор характеристик)
- Климатические условия (температура, влажность, давление)
- Результаты измерений (таблица с предзаполненными характеристиками, полями для ввода значений, статус соответствия НТД)
- Измерительные приборы (выбор из списка)
- Заключение (текстовое поле)
- Исполнители (список сотрудников из замоканного списка)
- Проверяющий (один сотрудник из замоканного списка)

## Технические требования

1. Использовать React + Ant Design
2. Для иерархических списков использовать TreeSelect
3. Все данные должны быть храняться локально (в состоянии приложения)
4. Формы должны быть адаптивными и поддерживать мобильные устройства
5. Валидация полей формы (обязательные поля, формат данных)
6. Поддержка русскоязычного интерфейса

## Файлы

- `description.md` - описание процесса ведения измерений
- `Подразделения.txt` - структура подразделений-заказчиков
- `rules.md` - правила для разработки
- `964 НМЭС-2023_КОС. 28-4-12.xlsx` - пример заполненного протокола
- `448 СМЭС-2023_ВЛ-0,4 кВ Ф-2 от КТП-95.xlsx` - дополнительный пример протокола

## Основные экраны

1. **Главный экран**: Карточка для доступа к реестру протоколов
2. **Реестр протоколов испытаний**: Таблица с протоколами, создание/редактирование/удаление
3. **План-график испытаний**: Placeholder для будущих версий

## Взаимодействие с протоколом

- Создание нового протокола через форму с предзаполненными характеристиками по выбранному виду работ
- Редактирование существующего протокола
- Просмотр деталей протокола
- Удаление протокола

## Дизайн требования

- Использовать компоненты Ant Design
- Цветовая схема: синий (#1890ff) как основной, зеленый для "соответствует", красный для "не соответствует"
- Легче читаемость таблиц
- Адаптивный макет для разных размеров экранов

## Примеры данных

Для демонстрации прототипа должны быть подготовлены:

- 2 виды работ с набором характеристик
- 20 объектов
- 2 заполненных протокола
- 10 измеряемых характеристик

## Дополнительные требования

- Поддержка поиска по протоколам
- Фильтрация протоколов по дате, виду испытаний, электролаборатории
- Экспорт протоколов в Excel (будущие версии)

## План разработки

1. Настройка проекта React + Ant Design
2. Создание главного экрана с карточкой для реестра протоколов
3. Реализация экрана реестра протоколов с CRUD-операциями
4. Реализация модальной формы создания/редактирования протокола
5. Реализация таблицы с результатми измерений с предзаполненными характеристиками
6. Добавление возможности выбора вида работ и автоматического заполнения характеристик
7. Реализация иерархического выбора подразделений
8. Наполнение прототипа тестовыми данными
9. Тестирование и оптимизация

## Ограничения прототипа

- Данные хранятся локально (не сохраняются при перезагрузке)
- Нет интеграции с внешними системами
- Функционал плана-графика не реализован
- Экспорт в Excel не реализован
- Реестры сотрудников, электролабораторий и заданий скрыты (замоканные значения)
